# Объединение xlamBOT 0.8.18 и Trio Safety

Версия результата: **0.8.18.post1**. Репозиторий публикации: https://github.com/bsdedus/xlamBOT-TrioSafety.

## Происхождение

- Поставка upstream: `Olegu621/xlamBOT`, коммит `912743a366ca5b51733088b4afee832ddd21adee`, ревизия обновления 7.
- Доступные исходники из истории: `8cb39f37f527eb5ec75bab13e404c28cf358803c`.
- База Trio Safety: `9c6f2047ea4f8965a3eb441320fd1fcdea58af99`.
- SHA-256 scripts.zip upstream: `1274e0dacdca0b1f7bc64557daff3dd452af5158c5085772e4479dc04672a59f`.
- SHA-256 runtime upstream: `28c6367fa03edb564325cc52aa4759395576eb39a962b6eeec7ab42d3a3c8089`.

В новой поставке опубликован Python 3.13 bytecode. Большинство модулей совпало с историческими исходниками при сравнении кода под Python 3.13. Изменения калибровки, OCR, выбора первой карточки и новых маршрутов восстановлены по дизассемблированию. Комментарии исходных новых функций недоступны; это проверенная интеграция поведения, а не побайтовая копия закрытых исходников. Результат остаётся совместимым с Python 3.12 и прежними профилями Trio Safety.

## Перенесено

- Общая боковая навигация, страницы устройств, настроек, обучения и калибровки.
- Закрепление одного бойца; автоматическая сортировка выбирает первую карточку.
- Координаты кнопок и области OCR сохраняются в профиле устройства.
- Библиотека записей, прогресс проверки, исключение кадров, разметка и YOLO-экспорт.
- Новые пять ONNX-файлов и каталог бойцов из проверенного runtime-архива.
- Подписанные накопительные обновления исходников и HTML из одного коммита собственного репозитория.

## Сохранено и исправлено при объединении

- Ограничение управления Trio Showdown, проверка свежих кадров, освобождение ввода, конечные ADB-тайм-ауты и единственный владелец scrcpy.
- Арбитр направления с газом, стенами и областью наблюдения; CPU fallback при ошибке GPU.
- Русские пояснения, анимации с reduced motion, сохранение черновиков настроек.
- Устранены двойной захват устройства, дубли методов watchdog и двойное начисление статистики результата при автоматическом слиянии.
- Записи обучения перенесены в пользовательский каталог, а не внутрь установленной программы.
- Незавершённый выбор закреплённого бойца не запускает следующий матч.
- Калибровка блокируется при работающем/приостановленном боте и при занятом другим процессом устройстве; снимок проверяется по идентификатору и разрешению.

## Проверки

158 автоматических тестов плюс 10 subtests прошли с обновлёнными моделями. Выполнена проверка синтаксиса JavaScript. Четыре используемые модели выполнили инференс через DirectML; диагностика собранного EXE завершилась успешно. Страницы и API калибровки/обучения в собранной программе вернули HTTP 200. Новая панель и библиотека записей проверены в браузере без ошибок JavaScript.

Эта проверка не заменяет длительное наблюдение в настоящих матчах. Новые веса модели газа не означают доказанную точность распознавания; качество игры и стабильность эмулятора требуют проверки на устройстве.
